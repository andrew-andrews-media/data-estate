Overview

The Data Estate Ontology describes a data estate: the repositories a person or small organisation keeps, the documents in them, and the control plane that governs them. It was built for one working estate, and is published so that others can describe theirs the same way.

Three ideas carry it. A repository not flagged sensitive is a data product, with a purpose, an owner, a tier and the repositories it draws on. New documents carry a short block of metadata (their type, status, domain, date and the entities they concern), and the catalogue infers the rest, marking which is which, so it can index everything without guessing. And the decisions, rulings and automated jobs that change the estate sit in the same graph, so a reader can follow a ruling to the decisions that cite it, the jobs those decisions cite and the files those jobs wrote.

The control plane has four parts. A catalogue build reads the registers and documents and writes the graph. SHACL shapes check the graph at every build and report what breaks a rule; nothing is fixed automatically. A nightly sweep reports when the graph has fallen behind its sources. A decision board lists every decision and action waiting on the estate's owner, and files each answer back into the estate.

Privacy is built in. The private graph holds names; the publication never does. What is published is the model and, in later releases, the estate's shape in banded counts. Instance data, names, paths, and anything in a repository flagged sensitive stay inside the estate. A leak gate checks every file before it is released.

It reuses open standards: DCAT, PROV-O, SKOS, DPROD, schema.org, the W3C Organization Ontology and Dublin Core, with SHACL for the rules. Where a standard has the term, the ontology uses it rather than minting its own.

The parts

Vocabulary: the classes and properties, and the standard terms they reuse.
Concept schemes: the closed value lists, from artefact types to job statuses.
Rules: the SHACL shapes an estate is checked against.
Queries: the competency questions, as SPARQL.
